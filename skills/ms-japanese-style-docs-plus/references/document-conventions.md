# 文書要素のルール - 公開資料ベース版

PowerPoint、Word、Excel に共通のルールです。
[Microsoft 日本語ローカリゼーション スタイルガイド](https://aka.ms/japanese-styleguide)
の §4.1.7、§4.1.9、§4.1.11、§4.2、§5.2、§5.4.5、§5.4.7 を根拠としています。
2026 年 11 月 21 日に公式配布 PDF の該当節を確認しました。

優先順位は [中心的なルール](./style-rules.md) の §0 > 公開ガイド > この要約です。
以下の文書構成は、本スキルの独自方針として公式規則と区別します。

## 1. 文書構成 (本スキル独自の方針)

- 見出し、列見出し、短いラベルは原則として体言止めにします。
  意味が分かりにくくなる場合は、短い動詞句を使います。同じ階層では形式を揃えます。
- 箇条書きは同じリスト内で文体を揃えます。文章はですます調と句点、
  短い語句は句点なしを基本にします。
- 表は列ごとに用途と文体を揃えます。説明文の列はですます調、
  短いラベルの列は語句を基本にします。
- 操作手順は番号付きにし、各手順を実行できる順序で記載します。
  注意事項と実行する操作を区別します。
- 参照先は実在する見出し、ファイル、URL を使います。存在しない節番号やリンクを作りません。

例 :

```text
## 共有設定の確認

1. [設定] を開きます。
2. 共有先を確認します。

対象 : 管理者
```

## 2. 製品名と UI 名 (公開ガイド §5.2、§5.4.7)

- 製品名、機能名、UI 名は正式な表記を確認します。勝手に訳したり短縮したりしません。
- UI にラベルがある場合は、原則として半角の `[]` で囲みます。
  例 : `[保存] を選択します。`
- ラベルのない UI 要素や、通常の文章中の製品名を無条件に `[]` で囲みません。
- 製品のバージョン番号、著作権表示、商標記号など固定文字列は維持します。
  権利表示を追加する必要がある場合は、公開されている正式な表示を確認します。

## 3. キーとショートカット (公開ガイド §4.1.11、§5.4.5)

- 英語のキー名と「キー」の間には半角スペースを入れます。
  日本語のキー名では詰めます。例 : `Alt キー`、`変換キー`。
- キー名はキーボードや公開仕様の表記に合わせ、UI ラベル用の `[]` で囲みません。
- 本文中の組み合わせは `Alt + Tab` のように半角の `+` で示します。
- UI、コード、設定値をそのまま引用した組み合わせは、元の文字列を維持します。

## 4. 数字とデータ (公開ガイド §4.1.7、§4.1.9、§4.1.11)

- 可変の数量は原則として半角数字で示します。例 : `3 件`、`12 月`。
  慣用語や固有名詞に含まれる漢数字を機械的に数字へ置換しません。
- 桁区切り、小数、時刻などは半角記号を使います。
  数字と単位のスペースは [中心的なルール](./style-rules.md) の §4 に従います。
- Excel の数値、数式、ID、コード、ファイル名などは文体調整の対象外です。
- 日付や単位の形式を変える場合も、元の意味と値を維持します。
  曖昧な日付や単位は推測せず確認します。
