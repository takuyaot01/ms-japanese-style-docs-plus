# 文書要素・操作手順

日本語 UI と表記の出典は [Microsoft 日本語ローカリゼーション スタイルガイド](https://download.microsoft.com/download/bb82f407-78f4-4df4-accd-d63ceaadd24a/jpn-jpn-StyleGuide.pdf) §3.2、§4.1.1・§4.1.7・§4.1.9・§4.1.11、§4.2、§5.2、§5.4.5、§5.4.7 です。手順の構成と操作の書き分けには、Microsoft Learn の [Procedures and instructions checklist](https://learn.microsoft.com/en-us/style-guide/checklists/procedures-and-instructions-checklist) と [Describing interactions with the UI](https://learn.microsoft.com/en-us/style-guide/procedures-instructions/describing-interactions-with-ui) も参考にします。これら英語資料は日本語特有の表記の根拠ではありません。優先順位は [SKILL.md](../SKILL.md)、半角記号とスペースは [表記ルール](style-rules.md) に従います。

## 1. 文書構成

次は読みやすさを目的とする編集方針です。

- 見出しや列見出しは、何を確認・判断できるかが分かる短い語句にします。箇条書きは同じリスト内で粒度と文体を揃え、短い語句は句点なし、文章はですます調と句点を基本にします。
- 表は列ごとに用途を揃えます。比較する項目や単位が分かる見出しを使い、短いラベルと説明文を混ぜません。
- キャプションや参照文は実在する図、見出し、ファイル、URL を指します。出力にない図表番号や節番号は作りません。

## 2. 操作する順序

1. 最初に達成することと開始位置を示します。前提の準備、権限、利用環境に条件があれば、確認できたものだけを先に示します。
2. 複数の手順は実行順に番号を振ります。単独の操作なら箇条書きまたは 1 文にして、番号は使いません。操作には場所と対象を含めます。同じ画面・対象で連続する簡単な操作に限って 1 ステップにまとめ、画面が変わる操作や独立した確認は分けます。
3. 条件分岐は操作の前に書きます。例 (架空の社内手順) : 「対象欄が空欄の場合は、確認済みの項目名を記入します。」注意や影響は操作の後に埋めず、操作の前に分けて示します。
4. 実行を確定する操作や、何を見れば完了を確認できるかを、分かっている場合に明記します。確定ボタン名、処理結果、確認メッセージを推測しません。

**Plus の表記** : 手順の番号には `1.` のように半角ピリオドを付けます。命令文を名詞句で止めず、原則として意味に合った「開きます。」「選択します。」などのですます調に統一します。これは日本語の文章を揃えるための本スキルの指定です。

## 3. 製品名・UI の表示名

- 製品、機能、画面の実際の名称を、対象製品・バージョン・表示言語・プラットフォームに合う資料または対象画面で確認します。違いが出る条件が未指定、または画面や経路を確認できない場合は、対象箇所を「未確認」とし、必要な情報を尋ねます。訳語、画面の階層、ボタンの有無、前提となる契約・権限を推測しません。
- 操作説明では確認済みの表示名を半角の `[表示名]` で囲みます。ラベルのないスクロール バー、通常の文中に出る製品名やファイル名は囲みません。場所の説明に必要なら、`[表示名] タブ` のように要素の種類を添えます。ファイル名、テーブル名、関数名、商標・権利表示などは表記を変えません。
- 公開日本語ガイド §4.1.1 に沿って、アクセス キーの付記、表示に併記されたショートカット、操作が続くことを示す末尾の `...` や `…` などは、**表示上の付加情報だと確認できた場合だけ**、説明文の `[表示名]` から省きます。正式名称の一部の記号は残します。画面の正確な引用、スクリーンショット、ログ、原文維持の指定では、付記や末尾の記号もそのままにします。架空の画面で `記録(R)…` の `(R)` と `…` が付加表示と確認できた場合、手順では `[記録]` とし、画面の引用は `記録(R)…` のままです。
- 短い経路を `>` で示す場合は、同じ種類の選択が続く単純で検証済みの経路に限り、前後に半角スペースを入れます。表示形式だけの例 : `[項目 A] > [項目 B]`。途中で入力、状態変更、別の画面への移動説明、判断が必要なら、`>` に詰めず文や番号付き手順に分けます。

## 4. 操作の動詞と状態

- 入力機器を限定しない場合は、対象を添えて「選択します」「入力します」「開きます」「閉じます」などを使います。マウス操作や特定のジェスチャーそのものが必要なときだけ、確認した対象環境に合わせて「右クリック」などを使います。
- トグル操作は対象と目的の状態を示します。書式例 (架空のラベル・画面) : 「[通知] をオフにします。」チェック ボックスでは、実態に合う「チェックを入れます / 外します」または「選択します / 選択を解除します」で、変更する状態まで示します。チェック ボックスという理由だけで「オン / オフ」にせず、コントロールの実際の状態表記や公式の説明がそうなっている場合に使います。
- 同じ操作・対象は同じ語で示します。異なる操作や送る先の違いがあるときは、すべて「選択」「送る」などに統一しません。

## 5. キーとショートカット

- 英字のキー名と「キー」の間に半角スペースを入れ、日本語のキー名は詰めます。例 : `Shift キー`、`変換キー`。キー名は実際のキーの表記や対象環境の説明を確認し、UI 名の `[]` には入れません。
- 同時押しは Plus の表記 `Ctrl + C`、順番に押す場合は「先に … キーを押し、次に … キーを押します」のように文章で区別します。アクセシビリティや作業の都合で役立ち、対象環境で確認できた場合に限って代替のキー操作を併記します。コード、ログ、画面引用などの固定表記 `Ctrl+C` はそのままです。

## 6. 数字とデータ

- 説明文の可変数量には原則として半角数字を使います。慣用語、商標、固有名詞の漢数字は置換しません。数値の表示例とスペースは [表記ルール](style-rules.md) §3・§4 を参照します。
- 日時・単位・範囲は受け手が一意に読めるようにします。年・時刻・タイムゾーンの補足は必要かつ根拠がある場合だけ。曖昧な日付や単位を推定で変換しません。
- Excel では短い列見出しや説明セルを整え、既存セルの値・型・数式、ID の桁、日付シリアル、参照、名前定義は維持します。既存のシート名やテーブル列名など、参照先になり得るラベルも無断で変更しません。表示形式を変える場合は、変更が依頼範囲にあり意味が明確なときだけとし、入力済みの値を打ち直しません。
