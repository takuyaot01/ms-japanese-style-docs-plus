# MS Japanese Style Docs+ - 表記ルール

日本語の PowerPoint、Word、Excel に共通する表記の要点です。出典は [Microsoft 日本語ローカリゼーション スタイルガイド](https://download.microsoft.com/download/bb82f407-78f4-4df4-accd-d63ceaadd24a/jpn-jpn-StyleGuide.pdf) です。入手先が変わった場合は [公式ガイド一覧](https://learn.microsoft.com/ja-jp/globalization/reference/microsoft-style-guides) を確認します。適用順は [SKILL.md](../SKILL.md) に従います。

## 0. 本スキル独自の出力方針

以下は **Plus 独自の指定** です。編集できる文章・説明ラベルに限り、公式の必須事項とは区別します。原文維持の指定、正式名称や確認済みの UI 名、正確な引用・ログ、URL、時刻、パス、コード、比率、ID、セル値、数式には適用しません。

- 全角の英数字と ASCII に対応する記号は半角にします。補足のかっこも `()` に統一します。波ダッシュ、全角スペース、三点リーダーは使わず、範囲は「から」か `-`、省略記号は `...` を使います。日本語の `。、「」『』・ー`、ASCII に対応する文字がない `°` `©` `®` `™`、矢印などは使用できます。カタカナは全角にします。
- 日本語の説明文ではコロンの前後に半角スペースを 1 つ入れます。例 : `日時 : 11 月 22 日`。行末のラベルならコロンの前にだけ入れます。`13:30`、URL、パス、`A1:B10` など固定文字列内のコロンは変えません。
- 中黒は名前のほか、短い並列語に使えます。例 : `受付・確認・回答`。カタカナ複合語の区切りには使いません。
- 説明文の同時押しは `Ctrl + C` のように `+` の前後を半角スペースで区切ります。固定表記の `Ctrl+C` は変更しません。操作手順は原則として `1.` で始まる連番、文末は「…します。」とします。詳しくは [文書要素・操作手順](document-conventions.md) を参照します。
- 日本語は `Yu Gothic UI`、英数字・ASCII 記号は `Segoe UI` です。混在テキストは対応するランまたは文字種別の欄で分けて指定します。別フォントへ無断で置き換えず、適用できない場合と適用を検証できない場合は区別します。

## 1. ボイス

公開ガイド §2・§2.1 を参照します。読み手の知識と目的に合わせ、要点を先に述べます。長い文は要点ごとに分け、読み手の次の行動が分かるようにします。分かりやすさのために事実、条件、否定、専門用語の意味は変えません。

## 2. 語彙と表記

公開ガイド §2.1.2–3、§4.1.3・§4.1.8 を参照します。

- 文脈に合う日常語を選びます。例 : 可能を表す説明なら「できます」、繰り返しを促すなら「もう一度」。専門用語、権限、機能名を一律に言い換えません。
- 主語が明らかなときに「あなた」「私たち」を補いません。担当が異なるなら「管理者」「担当者」など、実際の役割を示します。
- カタカナは全角、英数字は原則として半角です。かな・漢字・送り仮名や同音語は [表記の確認手順](kana-kanji-okurigana.md) に従います。

## 3. 句読点と記号

公開ガイド §4.1.9 を参照し、Plus の指定と異なる場合は §0 に従います。

- 文末は「。」、区切りは「、」。桁区切り、小数、時刻、日付の記号は半角です。表記例 : `1,250 件`、`2.5 kg`、`13:30`、`2011/1/13`。
- 補足に `()`、操作説明で表示名を示すのに `[]`、章名や書名には文脈に応じて「」や『』を使います。元の名前や引用の中の記号は見た目だけを理由に変えません。
- 範囲の両端を含むかどうかが重要な場合、記号だけで済ませず意味が明確な表現を使います。

## 4. スペース

公開ガイド §4.1.4・§4.1.11 を参照します。コロンおよび同時押しは §0 に従います。

- 全角文字と半角文字の間には原則として半角スペースを 1 つ入れます。例 : `Word を使用`、`第 3 章`、`Shift キー`。半角の `()` と `[]` の内側にはスペースを加えず、外側は前後が語なら区切ります。
- 「。」「、」に接するときや、半角スラッシュの前後にはスペースを入れません。語末の `?`、`!`、`...` の直前には入れず、後ろに別の文が続くときは区切ります。商標記号は直前の名称と詰めます。
- 可変の数値と単位は原則として区切ります。例 : `4 kg`、`3 件`。`50%`、`45°` のように `%` と角度の `°` は詰めます。写真や投影の `mm` など、例外は対象の節を確認します。
- カタカナ複合語は対象分野の定着した表記と公開ガイドを確認します。例 : `ページ レイアウト`。正式名称や UI 表記は維持します。

## 5. 動詞と文法

公開ガイド §3.2・§4.1.12 を参照します。

- 時制は実際の時点に合わせ、不要な未来表現、使役、二重否定を避けます。実施条件と結果を分け、必須を任意に書き換えません。
- 操作対象と動作を明記し、マウス・タッチなどを限定しない動詞を基本にします。利用者の操作とアプリが行う処理は別々に記載します。

## 6. 文体とトーン

公開ガイド §4.2 を参照します。短い見出し・項目名を原則として体言止めにするのは、本スキルの編集方針です。名詞句が不自然なら短い動詞句にし、同じ階層・用途では形式を揃えます。本文と説明文はですます調を基本にします。提案、報告、依頼の組み立てや敬語は [ビジネス文書](business-writing.md) を参照します。

## 7. 生成前の文面チェック

1. 見出しと本文の文体はそれぞれ揃っていますか。要点、条件、次の操作が分かりますか。
2. 編集対象だけに半角記号、かっこ、コロン、スペースを適用しましたか。固定文字列、数値、数式、ID、名前、引用は維持しましたか。
3. UI の表示名・経路・状態を裏づける情報はありますか。説明上の整形と正確な引用を区別しましたか。
4. 未確認の規則や不足の事実は該当箇所で示しましたか。推定やプレースホルダーを確定事項として見せていませんか。

フォント指定、描画、値などの保存結果は文面だけでは確認できません。ファイルを扱う場合は [SKILL.md](../SKILL.md) の生成後チェックを別に行います。
