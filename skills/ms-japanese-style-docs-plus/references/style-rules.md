# MS Japanese Style Docs+ - 表記ルール

PowerPoint、Word、Excel の文章に共通で適用します。
公開ガイドで確認できた規則と、本スキル独自の出力方針を整理したものです。

出典は [Microsoft 日本語ローカリゼーション スタイルガイド](https://aka.ms/japanese-styleguide)
です。2026 年 11 月 21 日に公式配布 PDF の該当節を確認しました。
PDF は同梱しません。入手先が変わった場合は
[公式ガイド一覧](https://learn.microsoft.com/ja-jp/globalization/reference/microsoft-style-guides)
から Japanese を選んでください。

優先順位は **§0 の独自ルール > 公開ガイド > この要約** です。
公開ガイドを確認できない判断は未確認と明示し、推測で規則を追加しないでください。

## 0. 本スキル独自の出力方針

ここは公式ガイドの必須事項ではありません。文章とラベルにだけ適用し、
製品名、UI の正式名称、引用した固定文字列、コード、ID、数値、数式は変更しません。

- 全角の英数字と ASCII に対応する記号は半角にします。補足のかっこも `()` に統一します。
  波ダッシュ、全角スペース、三点リーダーは使わず、範囲は「から」か `-`、
  省略記号は `...` を使います。日本語の 。、「」『』・ー と、
  ASCII に対応する文字がない `°` `©` `®` `™`、矢印などは使用できます。
- 日本語の説明文ではコロンの前後に半角スペースを 1 つ入れます。
  例 : `対象 : 管理者`。行末のラベルは前にだけ入れます。
  `13:30`、URL、パス、コード、`A1:B10` など固定文字列内のコロンは変えません。
- 中黒は名前のほか、並列の短い語にも使えます。例 : `準備・確認・実施`。
  カタカナ複合語の区切りには使いません。
- 日本語は `Yu Gothic UI`、英数字・半角記号は `Segoe UI` にします。
  混在文字列は文字種ごとに指定します。フォントを適用できない場合は、その制約を明示します。

## 1. ボイス

公開ガイド §2、§2.1 が根拠です。

- 読み手に寄り添う、自然で親しみやすい言葉を使います。
- 要点を先に述べ、短く明快な文章にします。
- 読み手が次に何をすればよいかを分かりやすく伝えます。

自然さを優先しても、事実、条件、否定、専門的な意味は変えません。

## 2. 語彙と表記

公開ガイド §2.1.2、§2.1.3、§4.1.3、§4.1.8 が根拠です。

- 堅い表現を文脈に合う日常語にします。例 : `できます`、`もう一度`、`詳しい`。
  用語や UI 名を機械的に置換しません。
- 主語が明らかなときは「あなた」「私たち」などを無理に加えません。
  読み手の役割を区別する必要がある場合は「管理者」などを明示します。
- カタカナは全角、英字と数字は原則として半角にします。
- かな・漢字・送り仮名に迷う場合は
  [表記の確認手順](./kana-kanji-okurigana.md) に従います。

## 3. 句読点と記号

公開ガイド §4.1.9 が根拠です。§0 の独自ルールが異なる場合は §0 を使います。

- 日本語の文末は「。」、区切りは「、」を使います。
- 桁区切り、小数、時刻、日付などの記号は半角にします。
  例 : `1,250 件`、`2.5 kg`、`13:30`。
- 補足は `()`、UI の表示名は `[]`、章名や書名は文脈に応じて「」や『』を使います。
- 範囲は「から」または半角ハイフン、省略記号は `...` を使います。
- 正式名称や引用した文字列の記号は、見た目だけを理由に変更しません。

## 4. スペース

公開ガイド §4.1.4、§4.1.11 が根拠です。コロンは §0 に従います。

- 原則として全角文字と半角文字の間に半角スペースを入れます。
  例 : `Copilot を使用`、`第 2 章`、`Alt キー`。
- 「。」「、」と半角文字の間、スラッシュの前後、かっこの内側には入れません。
- 語末の `?`、`!`、`...` の直前には入れません。後ろに別の文が続くときは区切ります。
- 数値と単位の間には原則として入れます。例 : `4 kg`。
  `%` と角度の `°` は詰めます。写真・投影の文脈での `mm` など、
  公開ガイドで例外とされるものは個別に確認します。
- 補足の半角かっこの外側は区切ります。ただし UI のアクセス キーや商標記号は詰めます。
- カタカナ複合語は公開ガイドと承認済み用語に従います。
  例 : `ページ レイアウト`。正式な製品名や UI 表記を優先します。

## 5. 動詞と文法

公開ガイド §4.1.12 が根拠です。

- 時制は実際の事実に合わせます。不要な未来表現や使役表現を避けます。
- 動作は簡潔に述べます。ただし、一般的でないカタカナ語を無理に動詞化しません。
- 二重否定を避け、条件と結果を明確にします。
- 語調の変更によって、必須条件を任意の条件に変えたり、処理の意味を変えたりしません。

## 6. 文体とトーン

公開ガイド §4.2 が根拠です。

- 本文や操作説明はですます調にします。
- 見出し、ラベル、キャプションは原則として短い名詞句にします。
  名詞句では意味が不自然になる場合は、短いである調の動詞句を使えます。
- 同じ階層の見出しや同じ種類の要素では文体を揃えます。
- 読み手の操作と自動処理を区別し、能動態と受動態を使い分けます。
- 顧客向けの説明は丁寧にしますが、過剰な敬語は避けます。
- 「弊社」は、Microsoft が提供側として説明する文脈に限ります。
  個人や別の組織を Microsoft として表現しません。

## 7. 適用チェックリスト

1. 本文、見出し、ラベルの文体が揃っているか。
2. 句読点、半角記号、スペースが §0、§3、§4 に合っているか。
3. 文章が明快で、事実や条件の意味が維持されているか。
4. 製品名と UI 名、数値、数式、ID を変更していないか。
5. 文書要素が [文書要素のルール](./document-conventions.md) に合っているか。
6. 未確認の表記や不足している業務情報を明示したか。
7. 指定フォントとレイアウトを生成後に確認したか。
