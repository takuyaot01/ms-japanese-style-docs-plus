# かな・漢字・送り仮名と用語の使い分け

[Microsoft 日本語ローカリゼーション スタイルガイド](https://download.microsoft.com/download/bb82f407-78f4-4df4-accd-d63ceaadd24a/jpn-jpn-StyleGuide.pdf) §2.1.2–3・§4.1.3 を基準に、文脈に合う語と表記を選びます。以下は公開資料による確認手順と少数の文例です。網羅的な辞書ではありません。

## 1. 確認の順序

1. 製品名、対象環境の UI 名、固有名詞、正確な引用、コードかを確認します。該当する文字列は本来の表記を維持します。
2. 語がその文で指す行為・物・条件を確かめます。同じ読みでも一括置換しません。
3. 迷った場合は公開ガイドの該当節と、文化庁が公開する基準を確認します。送り仮名は [『送り仮名の付け方』](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/okurikana/index.html) の [見方・使い方](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/okurikana/mikata.html) に従い、原則の「本則」、本則の当てはまらない「例外」、ほかに認められる書き方の「許容」を区別します。
4. 編集できる箇所では同じ意味で使う表記を揃えます。別表記が許容されるなら誤りとは説明しません。公開資料から確かめられず意味や手順に影響するときは「未確認」とし、原文または対象環境を確認します。

## 2. 送り仮名と確立した名称

下記は本文とラベルを切り分けるための、公開基準を踏まえた目安です。他の表記を一律に誤りとせず、実際の欄名、書類名、固有名詞は優先します。

- **動作やその名詞形** : 通則 6 を踏まえ、本文では「取り扱い」「申し込み」を基本にします。例 : 「機器の取り扱いを確認します。」「申し込みの手順をまとめます。」許容される送り仮名の省略もあります。
- **慣用が定着した名詞** : [通則 7](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/naikaku/okurikana/honbun07.html) の例に「受付」「申込書」「売上高」があります。たとえば、手続きの説明は「申し込みの内容を確認します。」、書類を指すときは「申込書の記載内容を確認します。」と書き分けます。
- カタカナは全角、英数字は原則として半角です。数量の表記例 : `6 か月`、`8 個`。単語を含む正式名称は変えません。

## 3. 意味が違う同音語や条件

同音語の区別は、文化庁公開の [『「異字同訓」の漢字の用法』](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/sanko/yoho/pdf/yoho.pdf) を参照します。以下の文例はこのスキルのために作成したものです。

- **送る / 贈る** : 「確認用の資料を担当者に送ります。」は届ける行為。「お礼に花を贈ります。」は贈り物を渡す行為です。画面の確認済みの操作名が `[送信]` であれば、説明では「[送信] を選択します。」とし、UI 名を「送る」に書き換えません。
- **合う / 会う** : 「条件に合う項目を選びます。」は一致。「会場で担当者に会います。」は人と対面することです。
- **以上 / 以下 / 未満 / 超える** : 条件の境界を明確にする編集上の工夫です。「3 件以上」と「3 件以下」は 3 件を含み、「3 件未満」と「3 件を超える」は含みません。例の数は製品や運用の制限ではありません。元資料が境界を示していない場合は包含・除外を推測しません。
- **場合は / ときは / には** : 条件、時点・状況、目的への導入のどれを示すかを意識します。例 : 「対象外の場合は記入しません。」「内容を確認するときは元の一覧を参照します。」「確認を始めるには対象を決めます。」文脈で読み分けられるかを優先し、一律の置換規則にはしません。
